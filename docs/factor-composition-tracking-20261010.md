# 固定权重组合与追踪来源（本地验收，2026-10-10）

本批补完此前已在工作区实现、尚未登记验收的固定权重组合，并接通因子研究 → 手动选择 → 追踪分组。未改任何缠论识别规则；**未部署生产**。此前 `tracking-history-signals-20261010` 的生产发布不包含此批因子修改。

## 使用

1. 在「量化研究 → 因子检验」选择 5—20 个标的和 2—4 个因子，展开「多因子组合」，勾选固定权重组合，明确配置每项的正／反向和权重。
2. 运行后同时保留原单因子报告，另显示组合评分、贡献、IC／分层、覆盖原因及各窗口检验。组合图可全屏，原始配置、各日评分和完整输入随研究导出。
3. 展开「从评分建立追踪分组」，选择组合评分或单因子，手动勾选具体标的、填写组名，再点击「保存原档并创建追踪分组」。没有默认勾选，不自动选出前 N 名。
4. 只有管理员／已指定用户能使用追踪操作。保存失败不会建立分组；分组失败仍保留已保存原档，重试复用原上传 ID。相同原档、依据和选择重复提交只返回已有分组，不覆盖其后续编辑。
5. 追踪分组展开「因子研究来源」，可查看原档 ID／摘要／版本、评分日期、原始选择与完整精度评分，并主动下载原档。分组成员后续修改不会改写初始选择；追踪分析历史也携带该来源。
6. 账户云存档只读重开同样提供显式新建追踪分组；仅重开不会创建分组、查询行情或计算。追踪分组也不会自动开始缠论分析。

## 组合口径

- 版本 `factor-composition-rank-v1`；每天取全部组成因子都有值的共同标的，至少 5 只。不是把全部历史摊在一起排名。
- 各因子以平均并列排名映射到 [-1,1]，乘用户显式方向和归一化固定权重，再相加。权重范围 0.01—100；不拟合收益、不按 IC 自动反转。
- 常数因子贡献为 0，但其原权重保留；缺失标的仍在结果中，分数为空，不填零、不回填旧日期、不对剩余因子重分配权重。
- 组合使用因子原值的截面排名，与单因子可选去极值／标准化路径分开；参数、实际权重、数据指纹、组合版本和原始因子定义冻结于结果。
- 复用多远期窗口、时间划分、共享任务进度和显式原档重算。组合错误不删除其他单因子结果。
- 组合评分、贡献、分层收益均不是持仓比例或可交易净值；尚未贯通实际成交、手续费／滑点／停牌等交易回测。

## 来源、安全和边界

新增 `POST /research/archives/{id}/tracking-group`：要求真实 Cookie、`X-Research-Owner`、本人存档 ID／摘要／版本、当前追踪权限和明确选择。服务端从原档取分数，不接收客户端给定的评分。跨账户即使管理员也不能读取他人原档。撤权会阻断；已删除原档需先恢复。

- 新桥接只接受白名单 A 股代码：SH6、SZ00／30、BJ43／83／87／92。研究输入原来没有证券类型字段，故不将指数、基金、债券或未知代码猜成股票；此类标的请按正确类型手动追踪。
- 只接受最新观测日有限分数；空值、重复、股票池外、缺失／错误因子都拒绝整个选择，不静默缩小。显示名称仅是现有用户显示标签，不是历史证券名称证明；名称未知明确待补充。
- 来源仍是 `client_archive_not_server_verified`：一致性摘要不是原行情真实性／计算真实性认证。完整研究保存在独立原档，来源记录和其下载用于核对，不把可编辑账户偏好当防篡改凭证。
- 新分组 SQLite 事务内追加，保留现有分组及其他偏好；50 组／40KB 分组／64KB 偏好上限失败时不部分写入。
- 追踪清单修改新增服务器版本比较。前端提交捕获旧版本，服务器事务内验证，旧页面不能覆盖新加分组；旧客户端缺少 `tracking_revision` 时拒绝更改追踪清单并提示刷新，普通偏好不受影响。账号切换和迟到响应继续隔离。
- 保存研究与建立分组是两次独立写入，不承诺跨库事务；界面显示已保存原档。分组删除后用户再次明确提交可重建，未实现永久操作收据。原档被永久清除后来源索引仍在，但下载需要先从既有备份恢复。
