# 后台计算持久化实施契约

状态：第四阶段实施中，已加入输入契约、事务存储、六类分派、独立工作进程/命令行服务、可选 Web 接入、寻优组合级/雷达条目级检查点，以及单股/组合/多策略的信号生成逐根恢复；当前生产与本地默认 Web 执行器仍为内存线程池，本文不代表生产切换或第四阶段全部完成。

## 必须保留的行为

- 任务仅本人可读、取消或恢复；管理员不自动取得他人的研究结果。
- 取消、超时、计算预算耗尽、行情不完整均不得返回冒充完整结果的排名或穷举结论。
- 不改变严格成笔、背离、M1、归属门槛、候选顺序和计算所用行情。
- 排队、执行、取消中均受账户与全局配额限制；控制面始终可以查询和取消。

## 当前接入点（已核实源码）

`web/routers/backtest.py` 有六类提交：单回测、组合、多策略、单策略寻优、全部策略寻优、信号雷达。行情在请求中取得；默认 memory 模式保留 `BacktestTaskRunner`，显式 durable 模式将规范化的请求/行情/雷达映射交给 `task_service` 冻结并入库，不把闭包传给工作进程。

当前 `task_runner.py` 只保存内存 `TaskState`；`resource_admission.py` 的共享租约保护真实线程生命周期，但不能充当持久队列或进程硬隔离。`_run_optimize_all` 可再启动进程池，因此不能只限制顶层任务数便宣称已限制总计算进程数。缠论/指标/风险/回放另有同步计算入口，最终也必须纳入执行预算和任务生命周期，而不只改六个回测接口。

## 实施顺序与验收

1. **任务与输入契约**：只接受内部登记的任务种类；持久化请求、真实输入、归属、参数、规则及代码版本。不从客户端接受任意导入路径、可执行代码或 pickle。DataFrame 往返须保留浮点精度、日期/时区、列顺序、必要 dtype、缺失语义及 `snapshot_metadata`，用真实计算的结果等价测试证明，不只验证能反序列化。
2. **事务任务库**：以 SQLite 事务完成提交、同账户去重、配额预占、领取和状态转换。完成结果、失败原因、检查点和来源证据可重启读取。结果保留按账户/实例字节与条数设限，不能淘汰活动任务；不得将内部 payload、owner 标识或凭证混进公开结果。
3. **独立执行与停止**：工作进程独立于 HTTP；限制全实例子进程和内存预算，不允许“全部策略”再无限嵌套启动子进程。只有实际工作进程退出后，取消/超时才进入终态并释放执行名额。使用每次领取的代次标识阻止过期进程发布结果；不能仅凭心跳过期便假设旧进程已死并无限重跑。
4. **检查点、恢复与缓存**：检查点关联完整输入指纹、执行版本、任务种类和进度。网格/策略/雷达子任务以及穷举路径可在已完成边界续算；单回测按可完整恢复的资金、持仓、策略及柱索引保存状态。尚无安全检查点时必须标明“从冻结输入重新计算”，不可伪称断点续算。已取消任务保留原终态；明确恢复创建关联的新执行记录。版本或输入不匹配拒绝复用，并给出原因。缓存仅复用完全相同上下文的完整结果，跨账户不得泄漏命中状态与内容。
5. **HTTP 与页面接入**：移除生产提交中的临时闭包，全部使用登记的任务输入；维持既有所有权及资源准入。页面区分排队、计算、请求取消、恢复等待及终态，刷新后重新读取，不依赖浏览器还活着。进度必须有真实分母；未知工作量不用虚构百分比。

## 不能省略的故障注入

- 两个请求同时提交相同输入、两个 worker 抢同一任务、取消与结果提交交错。
- 队列饱和、数据库写失败、磁盘配额不足、序列化失败均不泄漏执行名额或返回虚假任务成功。
- API 重启、worker 被终止、监督进程退出、旧进程恢复后迟到写入；不得重复发布或恢复取消任务。
- 暂停/丢失心跳不等于进程死亡；确认旧执行隔离后才允许重新领取。
- 去重和缓存随数据、复权、周期、参数、规则/代码版本变化失效；原快照仍可解释。
- 检查点前后结果与从头计算逐字段比较，包含浮点边界、顶底对称、缺失、未收盘柱及穷举结束标记。
- 普通账户、管理员、停用账户、其他账户的列表、结果、取消和恢复权限；不能只测试 UI 按钮隐藏。
- 原有账户/策略/偏好数据库迁移、任务数据库升级和旧版回滚使用副本演练；不覆盖真实用户新增记录。

完成证据必须包含真实跨进程/重启测试、六类现有后台业务回归、同步入口资源预算核验和浏览器交互；只有存储类单测通过不等于第四阶段完成。

## 已实现内核与下一步接入约束

- `task_payload.py`：登记六类任务；冻结完整请求、DataFrame、来源上下文及执行版本。显式编码非有限浮点、NumPy 标量、可空类型、时区和缺失值，保留字典/列/参数网格顺序；未知类型明确拒绝，不使用 pickle 或动态导入。恢复前检查契约、指纹、执行版本和容量；拒绝会改变原始数值的列/索引转换。
- `task_store.py`：独立 SQLite 数据库；事务完成提交、同账户同输入去重、领取、停止请求、结果发布与终态删除。配额保存在数据库中，由所有进程共用；启动时显式传入冲突配额即拒绝，不让不同进程各自放宽限制。缓存仅接受同账户、相同输入/执行版本的完整成功结果，可显式禁用完成结果复用；取消中、失败、已取消和超时结果不作缓存。
- 当前容量限制为逻辑记录/保留内容字节限制，不是操作系统磁盘、CPU、内存硬配额。超过保留容量时明确拒绝提交或将结果保存失败记为 failed，不自动删除用户记录，也不淘汰活动任务。后续必须继续落实监督进程和系统资源预算。
- 任务读取采用公开字段白名单；列表、心跳、领取、取消不读取大型输入 BLOB。内部执行凭据不得通过 HTTP 返回。`load_input` 同时核验代次、token、执行者身份、输入指纹和代码版本。
- 心跳陈旧只供监督器检查。`finish_after_exit` / `requeue_after_exit` 是**可信监督器接口**，存储类自身不能证明 OS 进程已退出；接入时必须先观察子进程真实退出，再调用。绝不能将 API 请求结束、取消按钮响应、心跳超时当作这个证明。
- `requeue_after_exit` 目前只表示从冻结输入重新计算，不是检查点续算。后续领取产生新代次和随机凭据，旧执行者不得读取、续心跳、发布或释放新执行；已有取消/超时请求在恢复时终结，不重新排队。
- 上述存储接口现已由独立监督器调用，见下节；HTTP 默认提交仍未接入。完整检查点、同步任务硬隔离、页面恢复及发布迁移演练仍未完成，不能据此称生产任务队列已上线。非正常监督器死亡的本机恢复实现见最后一节，不以该实现替代 Linux/生产验收。

## 独立执行与服务入口（已提供可选 Web 接入，未生产切换）

- `task_dispatch.py` 从登记种类及冻结的请求/行情重建六类任务。组合/多策略保留一一映射和原分仓，雷达保留错误行与缺失取数原因；不重新取行情，不把策略实例跨进程传递。
- `task_version.py` 使用安装包 Python 源文件的路径与内容、Python/平台/架构、数值依赖版本构建执行标识，不只读取 Git HEAD。开始与发布前复核，代码或运行版本不匹配不执行/不发布。此标识不是跨机器浮点完全一致性的数学证明。
- `task_worker.py` 通过私有 stdin 接收有界启动信息，不接受 pickle、任意模块名或计算函数。子进程将结果暂存为私有内容；由 `task_supervisor.py` 的实际 `Popen.poll()/wait()` 退出码决定是否公开。取消优先于迟到结果，异常退出即使已暂存成功也不发布为 done。
- 任务库升级到 schema 2，事务增加暂存字段；暂存也计入存储容量，恢复重跑清除旧暂存，保持原输入、结果、所有权与限额。已用 v1 副本测试升级和再次打开；尚不是生产数据迁移与回滚演练。
- 监督器核验账户启用状态，启动前和执行中检查；未知账户或查询异常按不可执行处理。原生计算不配合停止时，先 terminate 再 kill，真实退出前名额不释放。关闭时数据库异常也不能阻止停止自己创建的子进程；未保存成功的状态保留用于重试，而非伪造完成。
- 每个工作进程限制 CPU 时间、禁用 core dump、约束原生计算线程数；Linux 默认设置 2 GiB 虚拟地址空间上限，并保留宿主机更严格的现有限制。macOS 默认不启用地址空间限制，启动时明确提示；Windows 此独立服务明确拒绝启动，现有默认 Web 执行器不受影响。这些不是全局 RSS/磁盘/容器硬预算的完成证明；当前隔离 Linux 专项已通过，生产接入与全部资源验收仍待完成。
- 独立任务内 `optimize_all` 当前采用 `process_budget=1`，避免嵌套进程池突破共享预算；原请求 workers 字段仍保留，现有默认执行器仍保持旧并行路径。后续分片/检查点调度须利用共享名额实现有界并行，不能把当前内层串行当作全部寻优调度优化完成。
- Linux 安装父进程死亡信号，另有父管道断开监测。管道断开、子进程强制终止、优雅关闭后可由新监督器从冻结输入重新运行；突然死亡后的恢复另使用下述双锁协议。陈旧心跳不会触发自动重跑，不能仅按 PID/心跳猜测旧进程已死。

独立服务示例（任务库须已存在，且与已初始化账户库同目录；命令不启动 HTTP）：

```sh
EASY_TDX_CONFIG_DIR=/path/to/private-config easy-tdx research-worker \
  --database /path/to/private-config/research-tasks.db
```

此命令尚未加入生产编排；普通 `serve` 默认仍使用现有执行器，可显式配置 durable 进行配对验收。生产切换前还需完成检查点与恢复语义、同步预算、全局资源预算，以及包含审计日志模式预检的生产升级/回滚。

## 异常退出后的双锁恢复协议（本地实现，未部署）

- `task_guard.py` 的 `flock-v1` 仅面向同一主机的私有本地文件系统，不支持把任务目录放在网络共享盘后由多台机器使用。监督器在领取任务前持有自己的 OS 文件锁；每次执行另创建独立执行锁，先将 `guard_ready` 持久化，再通过 `Popen(pass_fds=...)` 把已加锁描述符交给子进程。父进程关闭自己的副本时不执行 `LOCK_UN`，子进程一直保留描述符到操作系统退出。
- 新监督器只检查带此协议的执行。取得旧监督器锁后重新核验代次，再尝试取得执行锁；两者都可取得才允许重新排队。若子进程被暂停但仍持锁，继续占用执行名额，不按时间或数据库 PID 杀进程，也不重复计算。监督器关闭时若数据库记账失败，仍保留自己的锁及已观察退出的句柄用于重试。
- 领取之后、持久化 `guard_ready` 之前崩溃，可能尚未创建执行锁；只有旧监督器已停止且 `guard_ready` 为假，这个缺失才可作为从未启动的协议状态处理。已 ready 的锁缺失、旧监督器锁缺失、权限/文件类型/身份异常，以及旧版无协议的执行都拒绝自动恢复，并在监督器 `recovery_issues` 中记录原因；尚待接入管理界面。
- 锁目录为当前用户私有 0700，锁文件 0600，拒绝符号链接、硬链接和路径/描述符 inode 不一致。数据库路径规范化，别名不会创建另一套锁。运行中不得删除或重建锁目录，当前不自动删除历史锁文件；安全清理及文件数量预算仍待补齐。
- schema 3 增加执行锁协议、启动准备状态及恢复次数/时间/原因。已有 v1/v2 记录仍保留原始输入、账户、结果与限额；旧的执行不会被伪造为拥有存活证明。公开字段只新增恢复诊断，不包含锁路径、owner 或执行凭据。
- 无法取得旧子进程实际退出码时，即使数据库里已有暂存成功也不能发布。恢复会清除暂存，从原冻结输入重新计算；这不是检查点续算。下一次领取使用新代次和凭据，迟到旧进程不能续心跳、读取或写入。取消和超时请求直接成为相应终态，不复活为排队任务。
- 验收：本机持久化/旧业务组合 292 项通过；隔离 Linux（原生产镜像依赖、当前源码只读挂载）177 项通过，含真实父进程 SIGKILL、已停止子进程的内核死亡信号和原生内存映射拒绝测试。测试容器限 1 CPU/1 GiB、非 root、无网络、无生产数据挂载，运行后自动移除。证据在 `output/platform-optimization-20261009/cold-recovery-{regression-final,linux-second}.log`；不把这组测试当作整个第四阶段或全站验收。

## Web 接入与状态面板（可配置验收，未生产切换）

- `EASY_TDX_TASK_BACKEND=durable` 显式选择持久队列；默认 `memory` 是过渡期旧行为。未知配置启动即拒绝，数据库失败返回明确错误，不静默改用内存线程池。后续生产必须把 Web 和 `research-worker` 配置为同一私有目录、源码/依赖版本，并先初始化任务库；当前没有自动改线上服务或 Docker 编排。
- 六类 HTTP 提交都在现有行情准入完成后冻结完整请求和实际帧；组合/策略槽位顺序、原始分仓、雷达错误行及源信息保留。持久化操作在有界计算线程执行，查询/取消/删除走独立控制面线程，不让 SQLite 写等待阻塞事件循环。入库前再次检查账户启用状态。
- 任务列表、读取、取消和删除均以当前已认证账户过滤；管理员不隐式读取他人任务。查询/取消不暴露 owner、输入、lease 或 worker 身份。列表无完整结果；控制面取消读取摘要，不读取完成结果大 BLOB。
- 任务响应增加存储模式、种类、与当前 Web 执行版本是否一致及恢复次数/时间/原因。旧版 pending 不被自动改用新规则，页面显示等待匹配版本并允许取消；旧的已完成结果仍可读。完成缓存复用时直接返回真实 done 与 reused，不伪报 running。当前缓存仍要求完整冻结上下文相等，未擅自忽略采集时间或来源元信息。

## 检查点与共享分片计划（组合级寻优已实施，其余未完成）

- 首先增加任务库内检查点契约：绑定任务输入指纹、源码/依赖版本、算法检查点版本和执行代次；与容量记账一同事务保存，读写均检查当前 lease。取消/超时不能借检查点复活，旧代次不能改写新检查点，损坏或不匹配必须报错，不能当作空状态重算后虚报续算。
- `ParamGridOptimizer.run` 当前每个组合均独立回测，可在组合完成边界保存无损结果及真实遍历索引；无效参数、计算失败亦要记录其位置和原因，避免把成功结果条数误作网格游标。恢复必须保留网格输入顺序、相同收益排序的稳定顺序、完整排行与热力图，不只保留 best，也不从舍入后的网页 JSON 恢复内部浮点状态。
- 全策略寻优应将策略/参数组合映射为确定的分片，由同一共享执行预算领取；不能以新建内层进程池绕开总进程数。需要验证重启前后顺序、异常策略、重复参数和无效组合一致，并保留完整任务来源证据。
- 雷达按冻结 targets 顺序恢复，每个已完成 target 的正常/失败结果与来源保持；组合、多策略及单回测涉及账户持仓、现金、委托、权益序列等内部状态，不能仅以外层循环索引声称完成逐根续算。应分别定义可验证的安全边界，记录尚不支持的粒度，不减少原六类任务范围。
- 验收至少包含：真实进程完成部分工作后强制退出，新进程只执行剩余工作，完整结果与不中断运行逐字段一致；存储故障保持前一完整检查点；取消/超时/版本变化不复活；配额、迁移、失效旧代次、并行归并次序及用户隔离测试。恢复计数、已完成/总工作单元与真正续算说明须由后端事实驱动，不使用假百分比。

### 当前已实现的检查点边界

- schema 4 的私有检查点使用既有无损 codec、16 MiB 上限和容量事务记账，绑定 task id/冻结输入指纹/执行版本；CAS 防止覆盖新检查点，lease 隔离旧执行。v1/2/3 升级不改旧输入和结果。取消、超时不能恢复，终态释放检查点；不将中间结果提供为 done。
- `ParamGridOptimizer` 单策略与 durable 全策略寻优已保存每一个实际处理组合，成功原始指标、invalid/failed 状态均按原顺序保留。已完成前缀经算法验证后才复用；数值不舍入，相同收益的稳定顺序、重复参数、最优点、完整排行及热力图与连续运行一致。保存错误不得被单点容错吞掉。
- `checkpoint_grid_points` 是已保存参数组合数，`resumed_grid_points` 是本执行代次实际消费的已验证前缀数，包含无效/失败参数组合，均不是全任务百分比。新领取/重排重置本次复用计数，最终结果保留本次复用事实，删除临时检查点。
- 进程级测试包括实际 kill 后新进程只执行剩余组合，以及真实 TaskSupervisor/worker 在 200 点网格中断、停止、重排、替换进程后结果等价。多策略完整检查点恢复时不重新执行任何已完成网格。阶段结果 79/148/34 项通过，最终组合结果以全站台账后续核验为准。
- 旧章节“重排不是检查点续算”描述的是 schema 3 阶段；当前仅在支持的算法且检查点完整通过验证时续算，其他阶段仍从冻结输入重算。下述 schema 5/6 补充了雷达和信号生成边界，但不代表成交/权益阶段、共享分片调度和全局硬预算完成。当前检查点改动均未部署，也未以旧 schema 3 的 Linux 测试替代新版验收。

### 雷达条目与信号生成逐根恢复

- schema 5 的雷达记录包括正常行、错误行、重复条目、完整来源和按冻结窗口生成的信号。已经保存的失败行不重新计算，不悄悄改变扫描顺序和统计；恢复验证通过才更新实际复用计数。
- schema 6 新增独立 `checkpoint_signal_bars` / `resumed_signal_bars`。单股、组合、多策略按槽位位置分区（不是按可能重名的标签），每 64 根及末根保存一次完整信号生成状态。未持久保存的尾部最多重算一个间隔；这些计数按槽位累计，不冒充已完成成交或全任务百分比。
- 保存现金/持仓**估计**、全部已生成信号、仍有效的止损止盈条件、自定义策略状态及下一根位置；不是只保存循环索引。恢复重新绑定冻结行情并初始化确定性指标，然后恢复完整状态，继续尚未处理的柱。佣金影响信号阶段的可买数量估计，纳入配置校验；不舍入内部浮点值。
- `Strategy` 默认不声明恢复能力。全部现有内置指标策略的 `next()` 仅修改引擎持仓/信号状态，使用显式版本契约；外部派生类不自动继承该无自定义状态承诺。需要自定义计数器、动态止损位等的策略必须实现 identity / export / validate-and-restore 接口，不持久化活对象或可执行代码。
- `SignalCheckpoint` 验证策略/参数/配置、行情形状和内容辅助指纹、完成位置、资金/持仓、信号顺序和日期、止损状态及自定义状态。完整输入/来源/执行版本和执行代次另由 journal/store 绑定，辅助行情哈希不替代无损任务指纹。状态损坏不能当作从头重算，写失败不能变成部分成功。
- 当前已完成的信号前缀可直接复用，**后续成交模拟、成本盈亏、权益曲线与绩效仍从完整信号重新计算**；指标初始化也仍重建。尚不宣称所有流水线阶段均有完整检查点，接下来须定义成交现金/真实持仓、执行游标、权益序列的可恢复状态，再推进共享并行与同步入口硬预算。
- 本地专项已通过全部内置策略、预热期、自定义计数器/有效止损、真实进程终止后恢复，以及三类实际监督器替换；更广 518 项首轮中 517 通过，旧来源测试替身因新增关键字签名不兼容失败，已修正签名且保留来源不变断言，最终复验以全站台账为准。生产数据未迁移。
- 最终组合回归已核验退出 0：521 项通过、7 条既有警告；全库严格 Mypy 280 源文件、Ruff/457 文件格式通过，前端 237+15 项测试及生产构建通过。迁移/恢复补充 76 项通过。详见全站台账及 `signal-bars-regression-final.log`，不替代完整全站、当前 schema Linux 或生产验收。

### 撮合、成本及权益的阶段内恢复（schema 7）

- 上节“从完整信号重新计算后续阶段”是 schema 6 时的边界。现在默认 OrderSimulator、移动加权成本和 PortfolioTracker 分别每 64 单元/末尾保存完整可恢复状态；三个计数独立按槽位累计，区分保存与实际复用，不等于任务完成。
- 撮合保存现金/真实持仓及每个输入信号对应的成交、拒绝或无成交记录；恢复复核成交字段及现金/持仓算术。成本保存 position_cost/size 和完整逐笔 pnl/cost_basis。权益保存现金/仓位/均价前缀，保留 NumPy scalar dtype 及未舍入数值，恢复后继续剩余柱。
- 输入交易/信号、配置、行情辅助哈希、算法 schema 和游标均需匹配；journal 另绑定完整无损输入、源码/依赖版本及 lease。写失败向外传播，损坏状态拒绝，不以重算掩盖失败；取消和终态仍不得复活/提前发布。
- 自定义滑点模型和 OrderSimulator/PortfolioTracker 子类默认不享有状态恢复承诺。自定义 ExecutionModel 仍从完整信号执行；后续确定性阶段须完整成交输入相同方可恢复。指标初始化及绩效统计仍重算，共享分片/全局硬预算仍未完成。
- v1–6 事务升级保留原数据与配额；真实 v6 信号检查点迁移后可继续。九组实际进程终止/替换（单股/组合/多策略 × 撮合/成本/权益）精确对照通过。最终组合 578 项通过，另从归档直接加载旧源码的 48 组精确对照通过；全库严格 Mypy 281 源文件通过。详细日志见全站台账。本版本未部署，旧 schema 3 Linux 证据不能替代新版迁移与生产验收。

### 分钟时间身份契约

- 信号保留完整 Timestamp，撮合/持仓不再把同日分钟柱合并为 YYYYMMDD。日期别名仅在当天唯一时可用；信息不足则明确拒绝。原日线整数输入继续支持，不修改成笔、背离、M1 和费用/仓位条件。
- 全部回测阶段检查点加入 `bar_time_contract=exact-bar-time-v1`，缺少或不匹配不得复用。信号顺序按冻结柱位置验证，时间戳按精确瞬间键（区分 naive/aware）验证，时区往返和 DST 不丢失；与原执行版本、无损输入指纹和 lease 共同生效。schema 7 数据库结构未变，生产未切换。
- 12 组实际进程退出/替换覆盖三类回测、四个阶段。恢复结果与不间断计算（包括来源元信息）完全相等；657 项最终组合通过，48 组归档日线精确对照通过。既有 252 年化口径仍待跨周期修正，不将时间身份修复等同于全部研究正确。完整记录和边界见全站台账。
