# 用户主动查询统计 · 2026-10-10

## 已变更的口径

查询记录不再根据“访问过某个行情接口”推断为用户操作。只有明确标记为用户主动发起、且属于服务器支持列表的请求，才记录到查询明细与主动查询次数。

保留：点击查询、分析、计算、刷新、明确的数据页签切换、手动 F10 条目选择、手动回放和对比、主动提交回测/寻优/雷达、追踪组分析。

排除：页面初始化、自动刷新、股票名称补全及其回退请求、默认板块成员预加载、自动多周期研究、任务轮询、URL 自动运行及未标记来源的旧客户端请求。后台内部行情获取不单独作为用户查询事件。

一次主动操作可能包含取行情与结构分析两个主要请求，仍按请求计数，不宣称是点击次数。批量追踪分析按实际发送的标的分析请求记录；辅助板块展开和名称查找不记录。

登录、IP 来源、外部归属地查询权限、活跃时长估算、请求权限校验及计算结果均保持原有逻辑。

## 实现与边界

- 前端默认来源为 `system`，主动操作通过 `queryAction(true)` 在实际 API 调用时标记 `X-Query-Origin: user`。
- 标记只存在于同步请求发送阶段，不持续到 Promise 完成；手动请求等待期间，并行轮询、名称补全或后续自动计算不会继承标记。跨 `await` 的主动后续请求须显式重新标记。
- 多周期自动研究与手动更新分别传入明确来源；仅手动更新写入查询记录。
- 服务端不接受请求体中的来源字段作为依据；只有头部精确为 `user` 才进入已有查询记录逻辑，登录身份仍由服务端会话决定。
- 来源标记是产品统计口径，不是防伪的人类操作证明或授权凭据。自定义客户端可伪造/省略标记，但不会因此取得额外权限。

## 历史数据兼容

旧记录没有来源证据，不能判断哪些是真实主动查询，因此不推测、不批量删除。

采用可重复执行的增量迁移：

- `activity_events.query_origin`：旧记录默认 `legacy`；新版主动查询写 `user`。
- `activity_manual_days`：独立记录新版主动查询次数；原 `activity_days.queries` 混合计数仍保留，不改变旧表列数。
- 查询列表排除旧版来源不明的查询；旧登录仍显示。汇总使用新计数，旧活跃秒数和登录次数不重置。
- 原有 90 天／10 万条留存限制仍适用，正常到期清理规则不变。

这意味着升级后主动查询次数从新口径开始，不沿用之前的混合次数。旧版本对日统计表的整行 INSERT 仍然兼容，并有回归测试覆盖；源码回退时不要删除新增表、列或整库覆盖。
