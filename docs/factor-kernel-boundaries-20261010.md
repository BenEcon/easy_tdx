## 两个已复现的问题

1. **缺失收盘价变成持平。** 旧 OBV 用 `sign(close.diff()).fillna(0)`，丢失价格与其后一根无法计算的差分被当作零贡献。5 根窗口、第 10 行缺失的合成例子仍输出 `50.63223046042335`，而不是缺失值。
2. **较早的大额累计量吞掉后续增量。** 第 3 行成交量设为 `1e25` 后，旧实现第 20—22 行输出全为 0；同一局部行情独立算为 `156.0212901426816、93.9606451976937、-2.015523514472426`。这是浮点累计偏置，并非行情实际失去趋势。

修改前专项测试 40 失败、16 通过（`obv-before-tests.log`）；这些失败包含待增加的版本说明断言，不声称 40 个独立算法错误。首次手算测试编写时已校正算术：`[0,20,20,-20,30]` 的斜率为 2，不是 0。

## 数学口径和实现

保留 `obv_trend` 标识、默认 20 根、可编辑 2—600 根及原 OLS 斜率含义。长度为 w 的完整窗口内，将首根 OBV 设为 0：这只减去一个对斜率无影响的常数，不需要窗口以前的成交量或价格。

令第 j 个相邻价格变化对应的有符号成交量为 `d[j]`，j=1…w−1，则斜率为：

```
sum(6*j*(w-j)/(w*(w*w-1)) * d[j])
```

这是展开 OLS 协方差后得到的等价形式；权重非负且和为 1，避免先生成极大的累计 OBV。正常有限行情与原全历史 OBV 回归数值一致（允许浮点舍入误差）。斜率不是归一化数值，单位为原成交量单位／K 线，不作为买卖建议。

- 窗口内全部收盘价必须是有限正数、全部成交量必须是有限非负数。
- 缺失、不合法价格、负量或无穷量使整个受影响窗口返回 NaN；不补价、不补量、不输出伪零。
- 无效行移出完整窗口后自动恢复。合法平价或零成交量的变化贡献为 0。
- 原始索引和长度不变；不修改输入。窗口按现存 K 线根数，不凭空补齐日历日期。
- 新版本 `obv-local-window-v3` 仅用于 OBV；其他内置因子的版本仍为 `builtin-parameters-v2`。
- 因子目录和研究结果携带实际说明、参数、版本与新的定义摘要；已有存档只读不换结果。显式重算保留原定义和来源，保存为独立新档。
