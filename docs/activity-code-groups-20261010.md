# 用户活动：标的名称与按代码分类

## 行为

- 管理员的用户活动明细增加可点击的「代码－名称」及市场，点击进入该市场代码的查询记录。
- 「按代码分类」统计所选时间、用户范围内的全部保留主动查询记录，不只聚合当前载入的一页。显示请求数、不同用户数和最近查询时间，支持继续分页。
- 输入完整代码可匹配不同市场的同码记录；输入 `SZ:000001` 等市场代码可精确区分。同一请求中重复标的仅计一次，批量请求按标的分别计入，所以分类计数之和不等于总请求次数。
- 无代码的概览请求不归类。原始记录缺失市场时保留「市场未记录」，不推测其是平安银行还是上证指数。原记录的批量 100 项上限继续有效，不补造未记录部分。
- 分类和筛选只影响查询明细，用户活跃汇总保持原来的时间／用户口径。

## 名称与自动查询

名称通过已有报价／证券资料服务及板块目录按需补全；内置常用指数沿用研究界面目录。同码股票按市场分批读取，不借用管理员自己的股票历史。展示当前简称，不宣称是查询发生时的历史名称。

补全仅用于显示，不改写历史记录，不计入主动查询。每次最多补全 200 个标的，每批至多 20 只证券；取消／切换筛选后停止旧补全并丢弃过期结果。离线或未知市场保留代码和「名称待补全」，可按代码筛选后刷新重试。

## 数据和权限

新增管理员专用 `GET /admin/activity/codes`，原事件接口增加 `code` 精确过滤与结构化 `targets`。接口均 `no-store`，未登录 401、普通用户 403；SQL 参数化，来源仍须为 `user`。名称服务、页面自动加载、轮询、来源未知旧记录不计入。

分类在只读查询中从已有允许列表元数据导出，不迁移／删除原日志，不重置统计计数。SQLite JSON 展开以完整标的键分组，不使用数组位置 `key`。

## 本地验证

- 后端活动、账户、安全定向回归 46 项通过；新增混合单标的／批量分类、市场碰撞、重复去重、完整范围与分页、时间／用户过滤、旧记录排除及权限测试。
- 前端完整回归 630 + 28 项通过，最终自动补全／无名称降级／市场隔离／请求规模限制／主动来源隔离定向复测 9 项通过。生产构建、Ruff、Mypy 319 源文件检查通过。
- WebKit 临时账户／合成活动验收：分类中的宁德时代 58 次、先导智能 2 次，沪深 `000001` 独立显示；名称补全前后原主动查询计数不增加。
- 分类点击下钻带入完整市场代码，手动筛选 `000001` 展示沪深两组；390 像素手机视口的整页宽度仍为 390，宽表格局部滚动。重启临时服务时出现一次预期心跳连接失败，恢复后功能正常。
- 10 万条合成记录、1001 个市场代码的完整分类本机约 1.05 秒；这是本机测量，不代表生产服务器时延。
