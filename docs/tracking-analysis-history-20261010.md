# 追踪分析历史保存 · 2026-10-10

## 范围与行为

本次针对「追踪标的」的每批分析，不更改缠论判定、行情复权或因子计算规则。已随后续买卖点和筛选功能一并部署，见 `deployment-tracking-history-signals-20261010.md`。

- 每批完成、部分失败、失败或手动停止后，自动生成独立的账户云存档。
- 保存分组与成员快照、分析周期、截止时间、结果、失败原因、规则版本，以及已取得的原始行情和元数据。
- 离开追踪页面不影响既有后台分析及完成后的保存；历史查看不会重新请求行情或重新计算。
- 历史支持只读查看、原始依据核验、导出、导入副本及现有回收站功能；再次分析不覆盖上一批。
- 保存失败明确提示，并保留待保存快照供重试或导出。重试复用同一存档 ID；未处理上一批前阻止开始新批次。
- 存档按账户隔离；切换账户会取消旧账户的上传状态，不把旧结果保存到新账户。创建追踪存档要求追踪权限。

## 边界

- 历史从更新后的新分析开始积累，无法恢复以前没有保存的结果。
- 此功能不是服务器持久任务队列：刷新或关闭页面仍可能中断未完成的分析。应等待「已保存」后再关闭页面。
- 使用既有云存档配额：单份 25 MiB、每账户总计 128 MiB、100 份。超额明确失败，不自动删旧记录或截断行情。
- 保存的是当时客户端的分析快照，并非服务器重新验证过的市场事实。保留原始精度，不以展示的两位小数代替计算依据。
- 行情请求参数、实际复权方式、所选周期、结果状态及原始行情完整性均进行格式与一致性校验。

## 实现入口

- 前端：`tracking-archive.ts`、`tracking-autosave.ts`、`tracking-session.ts`、`tracking-background.ts`、`tracking-analysis.ts`。
- 界面：`TrackingView.vue`、`TrackingArchivePreview.vue`、共用云存档列表与预览组件。
- 后端：`web/tracking_archive.py`、`web/research_archive.py`、`web/routers/research_archive.py`。
- 存档格式：`tracking-analysis-v2`，复用现有不可变存档和账户校验机制，不需数据库迁移。
