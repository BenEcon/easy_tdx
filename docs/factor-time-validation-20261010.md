# 因子时间划分与滚动检验 · 2026-10-10

本批为本地实现与验收，不部署生产。固定因子参数的时间外诊断已接入现有截面研究与原档；不是机器学习训练、自动选参，也不宣称自选股票池具有独立盲测或历史成分资格。

## 使用

进入「量化研究 → 因子检验」，选择股票池、因子、远期窗口，在「时间划分」中选：

- 全样本：保持原入口口径，无额外划分。
- 训练／验证／测试：指定训练和验证截止日（含当天），其后为测试。
- 滚动向前：指定训练、验证和测试根数，以及扩展训练窗／固定长度训练窗。测试窗按自身长度前移，不重复统计日期。

结果显示每个窗口三个区间的真实起止、日期数、边界剔除数、有效相关、RankIC／ICIR、分层差值、覆盖率和具体空值原因；测试日期汇总曲线可全屏，明细与公式可展开。全样本报告单独保留，不用全样本指标代替测试期指标。最后不足一个测试窗仍保留；如果连首个完整窗口也不够，明确报错，不暗中缩短参数。

## 计算契约

1. 版本 `factor-time-validation-v1`，使用明确股票池的合并日线观测日。根数不是自然日，也不是承诺完整交易所日历；每个标的缺失的中间行情使相应收益标签失效。
2. 因子按完整输入的因果历史计算，区间起点可以利用此前预热数据；不会在每个区间重新初始化因子。去极值／标准化仅用当天截面，不跨时间拟合。
3. 一个标签只有信号日和全部远期窗口都在本区间时才统计。每段最后 horizon 根剔除相关及分层结果，写明原因。即使全样本能看到区间后的价格，也不用于本区间的统计。
4. 测试总报告基于非重叠测试日期逐日汇总，不简单平均各窗口平均值。连续 20 个有效日均值不会跨越边界空缺连线。
5. 不自动选择参数、权重或方向；“训练区间”只是按时间命名的研究分区。重复查看测试结果后修改规则会污染样本外判断。多日收益本身有重叠，不以 ICIR 年化或声称独立样本。
6. 底层 API 同样拒绝零／负／非整数远期窗口、非法分层数和未知预处理，避免脚本绕过 HTTP 校验后误将历史收益当远期收益。
7. 时间检验合并日期上限 800，沿用股票池 5—20 只／最多 4 个因子的请求边界；不为过关截断日期或移除标的。现阶段仍是同步受控计算，后台长任务进度与持久取消尚待完成。

## 保存、兼容和展示

完整输入、配置、时间划分版本、各窗口结果、测试逐日数据和实际参数进入原档及指纹。只读打开、导入、导出不计算。显式复算仍用原输入及原实际参数，并生成可另存的新结果，不覆盖旧档。

只对已知的旧全样本配置做明确迁移：缺少 validation 的旧格式补为 null（全样本），记录 `legacy_full_sample_to_explicit_validation_none`，不会默认切成时间外检验。未知字段或不兼容配置拒绝复算，不忽略字段。

服务端原档验证核对日期计划、窗口数量、阶段起止、剔除数、测试日期不重叠及结构。校验不是对用户上传数值真实性的背书；不调用当前因子计算来“修好”旧记录。

页面沿用 frontend-skill 的紧凑暗色分区、分隔线、渐进展开和局部滚动，不增加卡片墙。相关系数图固定 −1 到 1，普通因子保持原尺度；缺值不连线。图表精度遵从已有精度选项，微小值采用科学计数，不在图表数据中乘百分数或舍入；百分数仅格式化显示。

## 测试证据

- 初版全后端相关回归 1207 项通过（`time-validation-backend-final.log`）；补充底层参数验证后的最新因子／存档／活动相关子集 884 项通过（`time-validation-core-final.log`），不是全仓库测试数。最新时间划分＋原档专项 69 项通过，其中时间划分 36 项。
- 手算 107 天样本分成 40／30／37：horizon=5 时边界各剔除 5，因子最初两天预热只影响第一段。滚动 20／20／7 测试尾窗逐日汇总；2 天尾窗全为空也保留。
- 修改未来价格和特征不会改变早期区间统计；追加数据后已完成窗口不变。全样本作为阳性对照能感知变更。覆盖 raw／MAD、1／5／10／20 远期、内部缺失、日期非法、窗口不足、配置篡改、已知旧档兼容与显式复算。
- 全前端 592＋28 项通过（`time-validation-frontend-final.log`）；生产构建、Ruff、Mypy 315 文件通过。保留既有 Starlette 弃用警告和构建大分块提示。
- 本机 20 只 × 800 日期 × 4 因子、77 滚动窗口，约 20.64 秒，返回报告约 2.63 MB（不含完整输入存档）。这是合成压力样本和单机测量，不是性能保证；未截断。日志 `time-validation-performance.json`。
- WebKit 隔离账号：默认需 200 根而实际只有 160 根时报错；80／30／30 配置产生两个窗口，尾窗 20 根被保留。日期分界模式生成 50 测试日／45 有效截面。配置修改同步清旧结果。保存、只读重开和完整导出均通过；只读前后计算请求记录相同。
- 390px 页面宽度为 390，存档对话框 374，表格局部滚动；测试曲线全屏及退出正常。浏览器用冻结平安银行数据乘时变倍率形成显式合成池，不能当作八只真实股票收益或投资效果。相关证据位于 `output/playwright/time-validation-*`。
- 活动记录仅一条登录和三次手动检验（一次不足数据失败、两次成功），初始化、保存、只读和导出均不增计。
- 最新构建再次刷新页面、只读打开已保存的两窗报告并在 390px 全屏核验，纵轴为 −1 至 1，边界空白不连线；截图 `time-validation-chart-bounded-mobile.png`。数据库查询次数仍为 3，自动加载未计入。图表辅助函数新增 3 项测试覆盖相关轴、微小值／原精度、百分数仅显示换算及原数据不变。
