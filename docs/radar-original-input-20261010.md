## 实现

- 持久任务模式读取原有 SQLite 无损任务输入，不新建行情数据库；内存模式新增有界冻结输入，扫描计算与复核使用同一份编码输入。全局 128 MiB、单账户 64 MiB，活动任务不淘汰；终态按缓存规则淘汰，单次超限明确要求减少标的。
- 完成的扫描结果附带任务编号，复核链接携带任务编号和原结果条目下标；不使用筛选后行号。旧缓存、旧链接仍明确标为重新取数，不自动冒充原行情。
- 只允许真实登录账户读取自己的原任务；管理员也不能读取别人的任务。预期账户头不匹配时拒绝；未完成、损坏、缺失、已淘汰／删除均停止，没有实时行情回退。读取为受限数据工作而非无配额轮询，响应禁止缓存。
- 核对原条目身份、参数、来源、复权、指纹及已收盘截止；前端另核对链接对应的市场、信号、顺序、价格关系、有限数和执行版本。原始价格精度不取两位小数后再计算。
- 个股与缠论复核均消费全部冻结 K 线。个股复核隐藏无效的日期裁剪控件，说明使用原预热区间；回测请求、历史记录和保存策略使用实际载入区间，而非 URL 辅助默认日期。输入／账户变化或卸载后，迟到数据不能写回。
- 依 frontend-skill 保持深色、紧凑、无新卡片的复核区，摘要仅说明数据是否核验，来源／保存期限／执行版本与详细限制默认折叠。

## 必须保留的边界

1. 冻结的是扫描时取得的数据，不证明该数据就是历史交易当日可见的版本。
2. 原输入读取不执行旧代码。版本变化时明确标注按当前版本分析；即便版本相同，当前资金、成本、规则设置也不等于原扫描信号或历史成绩重放。
3. 内存模式重启或淘汰即失去原输入；持久模式随原任务删除，不等于永久研究存档。
4. 保存策略保存配置和成绩，不保存永久原行情；以后载入策略重新取数仍可能变化。永久研究保存继续使用独立存档功能，跨入口完整衔接仍属后续工作。
5. 人工点击雷达扫描记为主动查询；路由自动复核及附带补全继续为系统查询，不混入主动查询统计。
