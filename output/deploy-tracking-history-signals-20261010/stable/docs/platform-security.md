# 平台安全边界与发布检查

本文件对应全站优化第二阶段的本地实现，不代表已经发布或完成全部安全验收。

## 权限矩阵

| 接口组 | 匿名 | 普通账户 | 管理员 |
| --- | --- | --- | --- |
| 认证状态、登录 | 允许，登录限频 | 允许 | 允许 |
| 首次初始化 | 仅账户库为空时 | 已初始化后拒绝 | 已初始化后拒绝 |
| 行情、资料、缠论、研究、回测 | 401 | 允许，仍受参数与资源约束 | 同左 |
| 策略、偏好、异步任务与结果 | 401 | 仅本人 | 仅本人，不默认跨账户 |
| 行情节点列表 | 401 | 只读 | 只读 |
| 节点测速、切换，账户管理、数据管理 | 拒绝 | 403 | 允许，敏感操作仍需独立校验 |
| 实时订阅 | 握手拒绝 | 有效会话及允许来源 | 同左 |

公共 HTTP 入口除认证路由外统一挂载受保护路由组。新增业务路由必须加入该组；新增独立公开入口须说明理由、资源限制和测试。未知 API 返回 404，不得回退为 HTML 首页。

## 来源、代理与 Cookie

- 默认只支持同源网页。跨域开发显式设置 `EASY_TDX_ALLOWED_ORIGINS=http://localhost:5173`，不能使用 `*`。
- 当前生产域名的计划配置：`EASY_TDX_ALLOWED_ORIGINS=https://tdx.bowenv.com`、`EASY_TDX_SECURE_COOKIES=1`。不要把本地开发来源带到生产。
- 代理必须正确传递 Host、HTTPS 协议信息和客户端地址；应用服务器仅信任已核验的反向代理地址，不能对公网启用任意来源的 forwarded-header 信任。登录限频读取 ASGI client，不自行信任任意 X-Forwarded-For。
- 如未正确传递客户端地址，同一代理后的用户可能共用对端登录配额；不能通过取消限频来掩盖配置问题。
- `easy-tdx serve` 增加 `--forwarded-allow-ips`（亦读取 `FORWARDED_ALLOW_IPS`），默认仅 `127.0.0.1,::1`。普通/reload 路径相同；只接受明确 IP 或规范 CIDR，拒绝 `*`、全网范围及其拆分写法、空项、拼错地址、主机名和 Unix socket 路径。空参数或 `--no-proxy-headers` 关闭转发头处理。配置在启动应用/浏览器前验证；本服务是 TCP 监听，不隐式解析代理主机名。
- Web extra 的 Uvicorn 下限与已核验 CI 锁定版对齐为 0.34，确保使用带 IP/CIDR 识别的传输实现；不把当前较新开发环境的行为假定为所有旧版都支持。用户直启 Uvicorn 会绕过上述 CLI 配置校验，必须自行遵守相同白名单限制。
- 可信代理拥有声明客户端身份的权限；白名单不能修复可信代理本身传递不可信头的问题。末级 Nginx 应覆盖（而非原样透传）`X-Forwarded-For` 为已核验的 `$remote_addr`、`X-Forwarded-Proto` 为 `$scheme`。应用不额外读取 `CF-Connecting-IP`、`X-Real-IP` 或 `Forwarded` 来改变登录配额。
- 浏览器写请求验证 Origin；不携带 Origin 的跨站 Sec-Fetch-Site 请求拒绝。非浏览器无 Origin 客户端仍需会话认证。
- WebSocket 单条应用消息限 4 KiB；`easy-tdx serve` 普通和 reload 模式均显式设置 websockets 后端、`ws_max_size=4096`、`ws_max_queue=8`，关闭压缩。直接启动 Uvicorn 的部署也必须设置对应参数，不能只依赖收到整条消息后的应用检查。完整消息及分片累计超限均由传输层拒绝。
- 实时连接配额存于同一账户 SQLite 库，跨 worker 共享：每账户最多 4 条，全实例最多 64 条，每连接最多 32 个订阅标的。租约每 15 秒续期、60 秒到期；正常/异常退出释放，崩溃遗留名额最多等待租约到期，已过期租约不允许复活。它是逻辑配额，不是 OS 层连接数/文件句柄的替代；不共享 SQLite 文件的多机部署不能视为共享限制。
- 控制消息使用跨连接、跨重连共享的令牌桶：每账户突发 40 条、持续补充 1 条/秒；实例突发 256 条、持续 8 条/秒。非法 JSON、无效操作同样计费；限频不等于严格固定分钟窗口。超限以 4429 和中文原因关闭；匿名和非法来源仍在握手时拒绝。不能为获得错误文本而允许未认证连接进入业务处理。
- 二进制控制消息以 1003 拒绝，超大消息以 1009 拒绝；会话撤销由心跳及接收/推送检查识别。行情轮询和事件推送有等待上限，盘中页面切换股票会断开旧连接，迟到的旧连接事件不改写新标的状态。
- 当前已增加下述 HTTP 取数/计算共享准入；仍需代理层连接/握手限速、独立进程硬隔离和完整生产验收，不能宣称防滥用已覆盖全部入口。

## 账户、会话与审计

- 首次管理员创建和最后一位启用管理员保留约束均使用 SQLite 写事务，跨 worker 生效。新安装应先通过部署环境配置管理员再开放公网，避免无人初始化的窗口。
- 角色变化、停用、改密码均撤销该账户现有会话；`POST /api/v1/auth/logout-all` 撤销全部设备会话。
- 登录固定窗口：同账户 8 次/5 分钟，同对端 30 次/分钟，实例 200 次/分钟；成功/失败都计入，持久化预占避免并发绕过。429 返回 Retry-After，不记录密码或原始对端。
- 账户审计最多保留 10000 条，涵盖创建、权限修改、密码修改、登录结果、退出、退出全部设备、节点测速/切换及任务取消请求。管理员通过账户管理的“操作记录”按类型/结果筛选并以游标分页；标准用户不能读取审计。
- 审计 details 使用白名单字段，禁止任意请求体、密码、会话令牌；节点地址属于配置节点信息，不是用户客户端 IP。任务取消记录证明请求已受理，不证明运行线程当时已退出，真实结果以任务状态为准。
- 旧审计表通过事务添加 details 列，保留原有记录；节点测速和切换使用服务侧 single-flight 与 shield，浏览器中断不会释放操作锁或跳过实际完成后的审计。
- SQLite 新增表使用幂等建表，不删除原账户、策略或偏好。升级前必须备份整个持久化数据卷；迁移/回滚演练仍为发布门禁。

## 后台任务控制（持久化队列的前置工作）

- 当前进程内线程执行器默认最多 16 个活动任务、每账户 3 个；超出返回 429 和 Retry-After。活动包含 pending/running/cancelling，结果缓存只淘汰终态记录，不淘汰排队任务。
- 默认从实际开始计算起计时 600 秒；超时通过计算检查点或状态读取发现。原生调用、子进程池无法即时强停，必须显示 cancelling 并继续占用配额，直至真正退出后记为 timed_out/cancelled。此实现不是硬超时进程隔离。
- 取消接口仅允许任务所有者，管理员不能取消他人的任务；未知和他人任务均 404。重复取消为幂等，终态不复活。取消或超时不得发布部分结果、排名或扫描列表。
- 个人账户显示最近 20 个本人任务，支持取消与失败原因；页面等待超时不冒充服务端计算超时。
- 结果和任务状态仍在内存，服务重启后丢失；尚未完成持久化任务、独立计算进程、去重、版本化缓存、断点与恢复。网页明确说明这一限制。
- 执行器自身仍有上述单进程限额；通过 Web 进入的工作另受下述跨 worker 共享准入约束，以更先达到的限制为准。它不是持久化任务队列，重启无法恢复任务结果。

## HTTP 取数与同步计算准入

- 业务路由在鉴权后、业务取数或计算之前取得 SQLite 资源租约。数据查询每账户 4、实例 24；计算/任务提交每账户 3、实例 8。两类配额独立且有界。满额返回 429 与 `Retry-After: 5`；配额数据库不可用时返回 503，不绕过限制。
- 控制面不占用研究配额：账户、管理员操作、任务查询/取消、策略库 CRUD、节点管理和静态策略/指标列表。它们仍受原有鉴权、大小、登录限频或节点 single-flight 约束。未知新增业务路由默认进入数据配额；计算路由必须检查分类测试。
- 后台提交从取行情前即占计算名额，任务引用继承同一名额，HTTP 响应结束不会释放。排队取消/提交失败释放任务引用；运行取消继续占用，直到实际线程退出。公开任务的 owner 校验保持不变。
- 同步回测、指标、因子/风险、个股/行业缠论和原有同步回放/研究入口通过受控线程执行，不直接阻塞事件循环。默认等待 120 秒；超时返回 504、不发布部分结果。协作检查点请求停止，原生函数不能即时强停，实际退出前保持配额。
- 同步线程使用真正的 concurrent Future 完成回调释放引用；取消 asyncio 等待对象乃至关闭事件循环都不等同于线程已退出。应用关闭时取消未开始的同步工作并等待运行线程结束。
- 每进程一个心跳线程每 15 秒续租；租约 90 秒过期，崩溃后遗留名额随后回收。租约丢失不发布结果。这仍是逻辑资源准入：暂停进程、长时间 GIL 独占或失联不能靠租约实现硬杀进程，需第四阶段独立工作进程隔离；多机必须共享配额存储。
- 此处限的是并发请求/逻辑任务，不等同于 CPU 子进程总数、请求速率或内存字节上限；全策略寻优子进程数及持久化队列的共享执行预算仍待统一。不得把本阶段称作全部资源保护完成。
